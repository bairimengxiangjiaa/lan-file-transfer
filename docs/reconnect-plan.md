# WebSocket 重连修复计划

## 1. 问题分析

用户反馈：页面上显示“已断开，点击重连”，点击后好像没有作用。

当前 `public/app.js` 的重连逻辑存在以下问题：

1. **缺少连接状态锁**  
   点击重连时没有防止并发点击的机制。用户快速多次点击会创建多个 `WebSocket` 实例，旧实例的 `onclose` 事件可能在新实例建立后触发，互相干扰，导致 UI 状态抖动。

2. **过期事件可能干扰新连接**  
   `connectWebSocket()` 直接用全局变量 `ws` 覆盖旧连接。旧连接的 `onclose` 事件处理器内部只依赖 `shouldReconnect`，没有判断事件是否来自当前活动连接，可能误判为“当前连接断开”。

3. **服务器未启动时无明确反馈**  
   服务器关闭后点击重连，流程为：连接中... → 连接断开，检测中... → 已断开，点击重连。整个过程很快完成，用户可能只看到一个很短的“连接中...”，随后恢复“已断开”，感觉像没有反应。

4. **状态栏事件绑定方式脆弱**  
   使用 `connectionStatus.onclick` 直接赋值，状态切换时反复绑/解绑，容易遗漏或覆盖。

## 2. 设计目标

- 点击重连后给出明确反馈：连接中 / 已连接 / 服务器未启动。
- 防止重连状态被旧事件、并发点击意外覆盖或循环抖动。
- 兼容服务器重启后再点击重连的场景。
- 改动尽量小，不引入额外运行时依赖。

## 3. 为什么这样设计

### 3.1 增加连接状态锁
新增 `isConnecting` 标志。`connectWebSocket()` 执行时先检查该标志，若已有连接正在进行则直接返回。这样可以防止用户快速点击产生多个 WebSocket 实例，也避免旧 `onclose` 触发新的重连风暴。

### 3.2 过期事件过滤
每次创建新连接前，先关闭旧的 WebSocket，并在事件处理器中通过 `event.target !== ws` 判断事件是否来自当前活动连接。这样旧连接的 `onclose` / `onerror` / `onmessage` 不会干扰新连接。

### 3.3 统一的状态栏点击事件
使用 `addEventListener` 一次性绑定点击事件，处理器内部根据当前状态决定是否响应。避免反复设置 `onclick` 导致覆盖或解绑遗漏。

### 3.4 明确的服务器未启动提示
`checkServerAlive()` 探测 `/files` 接口失败时，状态栏显示“服务器未启动，点击重连”，让用户知道当前无法连接是因为服务器没有运行，而不是点击无效。

### 3.5 不引入额外依赖
继续使用原生 WebSocket + fetch，不引入 `reconnecting-websocket` 等第三方库。本场景只需要轻量的状态管理和明确的用户反馈，引入库反而增加复杂度。

## 4. 功能边界

- **解决**：页面内 WebSocket 断开后的点击重连、并发/抖动防护、服务器未启动提示、服务器重启后重连。
- **不解决**：服务器端口漂移后的页面重定向、跨网络/跨域访问、浏览器离线但未触发 `ws.onclose` 的场景。
- **兼容性**：使用原生 WebSocket、fetch、AbortController；对不支持 `AbortSignal.timeout` 的浏览器提供降级。

## 5. 代码结构改动

### 5.1 修改文件

- `public/app.js`
  - 新增 `isConnecting` 状态锁。
  - `connectWebSocket()` 中关闭旧连接、过滤过期事件。
  - `ws.onclose` 中区分“主动关闭/过期事件”和“真正断开”。
  - `showDisconnected()` 中增加“服务器未启动”分支。
  - 在 `setupEventListeners()` 中为 `#connectionStatus` 统一绑定点击事件。
  - 改进 `checkServerAlive()` 的兼容性（`AbortSignal.timeout` 降级）。

- `public/style.css`
  - 增加 `.server-down` 样式（例如灰色），区分普通断开状态。

### 5.2 不新增文件

为保持项目结构简单，本次不拆分为新的 ES 模块，所有改动集中在 `public/app.js` 和 `public/style.css`。

## 6. 测试方案

### 6.1 单元测试（Node）

文件：`tests/reconnect.test.js`

- 使用 Node 内置 `node:test` + `node:assert`。
- 使用 `ws` 库创建本地 WebSocket 服务器，并提供一个 `/files` HTTP 端点。
- 在测试文件中给全局注入 `WebSocket = require('ws')`。
- 验证以下场景：
  1. 正常连接后状态为 `已连接`。
  2. 服务器主动关闭连接后，client 自动重连并在服务器恢复后回到 `已连接`。
  3. 服务器完全停止后，client 进入 `服务器未启动，点击重连`。
  4. 在 `服务器未启动` 状态下手动调用连接，先进入 `连接中...`，失败后回到 `服务器未启动，点击重连`。
  5. 服务器重启后手动连接，可恢复 `已连接`。
  6. 连续快速调用连接只产生一个活动 WebSocket。

### 6.2 手工浏览器验证

1. 启动服务，打开页面，确认状态为“已连接”。
2. 停止 Node 服务，等待状态变为“服务器未启动，点击重连”。
3. 点击状态栏，确认出现“连接中...”，随后回到“服务器未启动，点击重连”。
4. 重新启动服务，点击状态栏，确认恢复“已连接”。
5. 打开 DevTools Network 面板，过滤 WS，验证重连过程中没有大量并发的 WebSocket 连接。
